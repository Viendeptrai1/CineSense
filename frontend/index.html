Under the Hood

This demo shows a full NLP pipeline on real movie data: from crawling TMDB reviews, storing them in PostgreSQL, to training text models for recommendation and aspect-based sentiment analysis.

1. Data & Preprocessing

Raw data is crawled from TMDB (popular/top rated movies + reviews), then normalized into core tables: core_movies, core_reviews, core_genres. Non-English or very short/noisy reviews are filtered out by a lightweight language heuristic so that training focuses on English text.

Each review keeps author_avatar_url, rating, source_url, source_created_at and cleaned content (trim, deduplicate, safe length) to preserve full context for NLP models.

Feature mapping: the catalog page, detail page, review list and “Has reviews” badge all read directly from this processed dataset in PostgreSQL.

2. Recommendation Models

Offline training builds movie-level text profiles (title + overview + genres + review snippets), then trains two models:

  • TF-IDF baseline – sparse vectors + cosine similarity.
  • Sentence-BERT – paraphrase-multilingual-MiniLM-L12-v2, 384-dim embeddings.

Training scripts live in training/ and export artifacts (movie_index.json, similar_by_movie.json, embeddings) that the API loads at startup.

Feature mapping: “Top Reviewed Picks”, “Recommendation Search” and “Similar Movies” on the detail page all call the recommendation API, which reads these artifacts.

3. Aspect-Based Sentiment (ABSA)

A separate ABSA pipeline is trained in notebooks/kaggle_absa_train.ipynb using labeled data under training/data/absa/. The deployed model exposes a single endpoint: POST /absa/analyze.

Feature mapping: the “Aspect-Based Sentiment” box on the movie detail page calls this endpoint. For each movie it returns pairs like (aspect = script, sentiment = negative, score = 0.58).

4. End-to-End Flow

The full system follows a clean separation:

  • ETL: crawl TMDB → write to core_* tables.
  • Training: build movie profiles → train TF-IDF / Sentence-BERT → export artifacts.
  • Serving: FastAPI loads artifacts + Postgres → frontend calls REST endpoints.

This page is designed so instructors can see exactly which model is used for each feature and how the text data flows through the system.
